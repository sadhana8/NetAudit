What NetAudit is

NetAudit does not control a real router. It reads an uploaded RouterOS export file and turns the configuration into simple audit results: score, issues, evidence, reports, network view, and hardening guidance.

Purpose

Configuration review

Checks whether a MikroTik configuration is safe enough before use, after changes, or during review.

Input

RouterOS export

Uses a MikroTik .rsc export only. No router password, live login, or network scanning is needed.

Output

Risk findings

Shows the problem, severity, line evidence, reason, and recommended fix.

Result

Audit record

Saves completed audits so users can reopen results, compare two audits, and export PDF or CSV reports.

Project need

Why NetAudit is needed

Most home users in Nepal use the basic Wi-Fi router given by their ISP because it is enough for normal internet. MikroTik is used when a network needs more control, such as routing, firewall, hotspot, VPN, bandwidth control, or many users. NetAudit is needed because powerful RouterOS settings can also create risk: open management ports, weak firewall rules, unsafe NAT, DHCP conflicts, or insecure defaults.

Risk

Exposed services

Finds router login services like Telnet, FTP, Winbox, or SSH when they are open too widely.

Risk

Firewall weakness

Detects firewall rules that allow too much access or leave weak protection.

Risk

Address conflict

Finds duplicate IPs, overlapping networks, invalid DHCP ranges, and missing pools.

Risk

NAT exposure

Checks NAT and port forwarding rules that may expose internal services.

System workflow

How NetAudit works

The workflow is simple: upload a RouterOS file, run analysis, read the result, then open the next module when needed.

Step 01

Upload export

Select a RouterOS .rsc file. NetAudit checks the file type and size.

Step 02

Parse configuration

NetAudit reads RouterOS commands and separates interfaces, IP, DHCP, firewall, NAT, routes, and services.

Step 03

Score risk

Rules find problems, assign severity, and calculate the audit score.

Step 04

Review guidance

Open the report, network map, attack surface, hardening script, or comparison as needed.

ML risk prediction

Small ML layer for overall risk

NetAudit first checks the file with rules. After that, a trained K-Nearest Neighbors model reads the audit pattern and predicts whether the router looks low, medium, high, or critical risk.

Learns from

Labeled audit profiles prepared from known safe and unsafe RouterOS cases.

Looks at

Score, finding counts, severity counts, and weak areas like firewall, NAT, DHCP, routes, and services.

Shows

Predicted risk level, priority, confidence, nearest learned profile, and short reason.

System modules

What the system provides

NetAudit is split into useful modules. Users can follow the full audit flow or open only the module they need.

Core

Audit result

Shows score, main issues, evidence, and simple fixes.

Core

Network map

Shows WAN, LAN, interfaces, IP addresses, DHCP, routes, and NAT.

Core

Attack surface

Shows open services, risky WAN access, NAT exposure, and high-risk entries.

Core

Hardening script

Creates RouterOS fix commands for review. It does not apply them automatically.

Support

Audit comparison

Compares two audits to show what improved, what is new, and what is unchanged.

Support

Report exports

Exports PDF and CSV reports for submission or documentation.

Support

Sample library

Provides ready test files for secure, firewall, DHCP, NAT, route, and service cases.

Support

Evaluation module

Checks rule performance using labeled test cases and evaluation metrics.

System boundary

Reviews files, not routers

NetAudit reviews uploaded RouterOS export files without connecting to live routers. It helps users understand configuration risk while keeping router credentials outside the system.

No login

It never asks for router usernames, passwords, or SSH keys.

No live access

It does not connect to MikroTik devices or scan networks.

No auto change

Generated commands are for human review before use.

No hidden action

The system only analyzes files that the user uploads.
